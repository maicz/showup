# Architecture Decision Records

ADRs capture decisions that constrain product, security, deployment, or operations work. They are short, immutable once accepted, and numbered in the order accepted.

- Start from [0000-template.md](0000-template.md).
- Use `NNNN-short-title.md`; never renumber accepted records.
- Status is `Proposed`, `Accepted`, `Superseded by ADR-NNNN`, or `Rejected`.
- State the decision, context, consequences, and links to implementation/evidence. Update a later ADR to change a decision; do not rewrite history.
- Keep secrets, credentials, and private infrastructure addresses out of ADRs.
